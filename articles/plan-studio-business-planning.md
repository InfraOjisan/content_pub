## はじめに

このシリーズでは、AIに小説を書かせる「制作スタジオ」を作ってきました。前々回、道具を [novel_studio v1.0](https://zenn.dev/infra_ojisan/articles/ai-novel-studio-part6) としてまとめて公開し、前回は [使い方の解説（1/2）](https://zenn.dev/infra_ojisan/articles/novel_studio_install_and_operation) を書きました。

前回の最後に「案出しをうまく使えば新規ビジネス・新規サービスの企画案も作れる」と書きました。今回はそれを本当にやった話です。novel_studio の企画コンペの部分だけを切り出し、**商品・サービスの企画用の道具 plan_studio** として分けました。

https://github.com/InfraOjisan/plan_studio

テーマ（ジャンル・顧客層・コンセプト・開発規模・調査事項）を入れると、複数のモデルが企画の素案を出します。似た案と外れた案を見分け、選んだ案から企画原案（企画書のベースになる文書）を作り、最後に PowerPoint の Copilot・Claude・ChatGPT・Gemini に渡せば企画書になる「たたき」まで、一つの画面で進みます。novel_studio と同じく Python の標準ライブラリだけで動きます。

小説を書きたい方は読み飛ばして大丈夫です。逆に「AIに企画をがんがん出させて、人間が選んで経営層に出す」をやってみたい方は、この記事だけでインストールから企画書のたたきまで行けるはずです。

前半は novel_studio から何を変えたかと考え方、後半は画面を使った使い方です。

## 先に結論

- novel_studio の「企画コンペ → 分類 → 人が選ぶ」は、**そのまま事業企画に使えました**。20案を出させ、分類し、選んだ案から企画原案を書かせ、プレゼンの構成案を作り、Gemini にスライドにしてもらうまで、**約1時間**でした。
- 小説と違って、事業企画は **めちゃくちゃ収束します**。ただ、これは弱点というより情報です。20案がこれだけ同じ型に寄るなら、ほかの会社が AI に同じことを頼んでも同じ案に着きます。**収束の強さは「その市場はすぐ混む」の目安** として読めます。
- 一番気を使ったのは文章の上手さではなく **数字の出どころ** です。もっともらしい作られた数字は、事業企画では小説の矛盾よりたちが悪いからです。
- スライドそのものは作りません。体裁は Copilot や各社のアプリが得意で、しかも速く変わります。こちらは「何枚目で何を言うか」と、渡す材料と依頼文までです。

## 1. novel_studio から何を変えたか

### 工程

| | novel_studio | plan_studio |
|---|---|---|
| 一 | テーマ（ジャンル・題材・章数・読者・結末） | **テーマ**（ジャンル・顧客層・コンセプト・開発規模・入れたい／入れたくない・調査事項、任意で自社の前提・目標の規模感） |
| 二 | 提案（あらすじ・見せ場・何が面白いか…） | **提案**（企画タイトル・概要・必要なリソース・マーケット・判断、字数の上限つき） |
| 三 | 分類（物語の骨格） | **分類・選ぶ**（事業の骨格） |
| 四 | BRIEF → 確定 → CANON → 執筆 → 校正 → EPUB | **企画原案**（6節＋要確認事項） |
| 五 | | **企画書たたき**（スライドの構成案と、各アプリへの依頼文） |

執筆エンジン（CANON・章の執筆と審査・校正・EPUB・表紙）とハーネス用の試験は外しました。git の履歴は novel_studio から引き継いでいるので、どこから分かれたかは追えます。

### 素案の欄

小説の企画案は「あらすじ・見せ場・何が面白いか」でしたが、事業の素案は判断の材料にしました。

| 欄 | 上限 |
|---|---|
| 企画タイトル | 50字 |
| 判断の一言（例：「国内は3年ブルー、海外は既にレッド」） | 30字 |
| 企画の概要 | 1000字 |
| 企画実行に必要なリソース | 500字 |
| マーケットの状況、規模 | 500字 |
| 判断（いま／3年後／5年後、国内と海外、参入の窓と撤退の目安） | 500字 |
| 出典 | — |

「判断の一言」は、20案を一覧で見比べるときに効きます。字数は上限の1.15倍までは許します。超えたら一度だけ「内容を削らず言い回しを詰めて」と頼み、それでも超えたらカードに「字数超過」と出して受け取ります。

### 骨格

分類のやり方は novel_studio と同じです。モデルには骨格の抜き出しだけを頼み、似ているかどうかは道具が数えます。ただ、骨格の中身は事業向けに作り直しました。

| 欄 | 意味 | 選択肢の例 |
|---|---|---|
| customer | 誰の | 中小製造業の経理、自治体の窓口 |
| pain | 何の課題 | 監査対応の手間、夜間の人手不足 |
| solution | 解き方の型 | SaaS／代行・BPO／マッチング／ハード＋保守／コンサル・研修／データ提供／統合SI |
| revenue | 儲け方 | 月額／従量／成果報酬／売り切り／保守／手数料／広告 |
| edge | 勝ち筋 | 価格／品質・精度／規制対応／データの蓄積／既存顧客と販路／ネットワーク効果／速さ |
| market | 市場の型 | 既存の置き換え／新しい市場／ニッチの深掘り／海外の持ち込み／制度・規制起点 |

小説の「誰が欺く・何を隠す・どの層で驚かせる・何がひっくり返る」に当たるものです。語は選択肢から選ばせます。言い換えをさせると、同じ骨格が別物に見えてしまうからです。

### 企画原案

選んだ案から、企画書のベースになる文書を作ります。

| 節 | 目安 |
|---|---|
| サービスの概要 | 2000字 |
| マーケットの状況とインパクト | 1000字 |
| 当社の必要リソースと目標売上・目標利益 | 1000字 |
| リスクと対策 | 1000字 |
| 概要設計 | 3000字 |
| 販売方法・アプローチ | 1000字 |
| **要確認事項** | 推定の数字・仮定・未調査の点と、その確かめ方 |

リスクは「回避・委任・移転（譲渡）・転嫁」のどれで扱うかを書かせ、どれにも当てはまらず残ったものだけを「受容」として理由を書かせます。「リスク受容」で済ませがちなところを、最後の手段に押し戻すためです。

### 両方に入れたもの（今回の改修）

使っているうちに困ったことが二つあり、plan_studio と novel_studio の両方に入れました。

- **選んだ案だけを分析・ファイル出力する。** 案を大量に出すと、全部をまとめて分析には投げられません。案の左上の印で選び、画面のいちばん下の帯から「分析する」「ファイル出力する」を押します。出力は Markdown（一覧表＋全文）・CSV（Excel 用）・JSON です。
- **分析を小分けにする。** 前回の記事で、MiMo V2.6 Pro の分類が30分で落ち、Qwen3.8 Flash でも50分かかった、と書きました。8案ほどを一度に頼むと、OpenRouter 以外の上流のプロバイダは時間切れで諦めます（OpenRouter は上位のプロバイダへフォールバックするので表に出ませんでした）。そこで、骨格は3案ずつ・同時2本までに分けて頼み、落ちたら1案ずつに分け直し、取れた分からその都度保存するようにしました。AI に読ませる分類には、本文ではなく骨格の一覧だけを渡します。

## 2. 考え方

### 合議は外れ値を生まない。事業企画ではもっと生まない

novel_studio で分かったことはそのまま当てはまりました。複数のモデルに出させた案は、似た型に寄ります。事業企画ではそれがもっと強く出ます。もともと学習データに事業の定石が多く、モデルが得意なところだからだと思います。

ただ、事業企画では収束そのものに意味があります。

- **収束した型**：どの会社の AI に頼んでも出てくる案。つまり、すぐ混む市場。
- **外れ値**：差別化の候補。拾うかどうかは人が決める。

分類は良し悪しではなく、「型への寄り方」を見せるためのものです。

### 数字の出どころを三段で押さえる

事業企画で一番危ないのは、もっともらしい作られた数字です。三段で押さえています。

1. **素案**：数字には出典を書くか、「推定」と書いて筋道（社数×単価など）を一言添えさせます。OpenRouter なら Web 検索（`:online`）で確かめさせ、URL を出典に残せます。
2. **原案**：確かめていない数字や仮定は、「要確認事項」に「何を・どう確かめるか」と一緒に残させます。
3. **たたき**：原案にない数字がスライドに出たら、機械で警告して画面で印をつけます（12,000 と 12000 は同じ数字とみなします）。

### 中身を作る工程だけ上位モデル

- 提案：安いモデル・無料のモデルを並べて数を出す（発散が目的）
- 骨格の抜き出し：判定がぶれない中位モデル
- 原案：中身を作る工程なので上位モデル
- たたき：中身は原案で決まっていて、並べ替えと要約だけなので中位モデルで足りる

上位モデルにたたきを組ませると、余計な提案が増えて人の判断が揺れます。

### スライドそのものは作らない

たたきは「1枚＝1メッセージ」の構成案です。各スライドに、タイトル・言いたいこと（結論を一文で）・箇条・図表の指示・話すこと・原案のどの節から取ったか、を持たせます。2枚目で結論（何を・いくらで・いつまでに・何を決めてほしいか）を先に言い、最後の1枚は「お願いしたいこと」にします。

これを、渡す先ごとの形で書き出します。

- **PowerPoint の Copilot**：Word（.docx）。見出し1がスライドのタイトル、見出し2が言いたいこと。Copilot の「ファイルからプレゼンテーションを作成」に渡します。
- **Claude・ChatGPT・Gemini**：依頼文を先頭につけた Markdown。
- **Marp**：AI を通さずに、その場でスライドとして見る用。

## 3. 使い方

### 準備

前回の novel_studio とほぼ同じです。

~~~bash
$ git clone https://github.com/InfraOjisan/plan_studio
$ cd plan_studio
plan_studio$ vi .env
~~~

.env の例（標準は OpenCode Go、いざというときは OpenRouter）

~~~Plain
PLAN_LLM_BASE_URL=https://opencode.ai/zen/go/v1
PLAN_PROVIDER_APIKEY=[YourOpenCodeAPIKey]
# OPENROUTER_API_KEY=[YourOpenRouterAPIKey]
~~~

* novel_studio と同じ `NOVEL_LLM_BASE_URL`・`NOVEL_PROVIDER_APIKEY` もそのまま読むので、novel_studio の .env をコピーしても動きます。
* OpenAI 互換の窓口ならたいてい使えます。社内のモデルルーターにもつなげます。

起動します。novel_studio と並べて動かせるよう、ポートは 8790 にしてあります。

~~~bash
plan_studio$ python3 studio/server.py
plan_studio: http://127.0.0.1:8790  （企画フォルダ .../plan_studio/works、モデル https://opencode.ai/zen/go/v1、キーあり）
~~~

http://127.0.0.1:8790 をブラウザで開きます。

### 一 テーマ

「新しい企画」を押すと、テーマのフォームが出ます。

![](https://static.zenn.studio/user-upload/d30d974aaa0c-20261016.png)

「自社の前提」と「目標の規模感」は任意です。ただ、書いておくと原案の「当社の必要リソース」と「なぜ自社か」がぐっと具体的になります。今回は「SFA や CRM の導入が進まない現場で、各種リストから潜在顧客化を進めるマーケティング」をテーマにしました。

### 二 提案

モデルを選んで案を出させます。小説と同じく、モデルはあまり賢すぎない方が発散します。無料モデル・安いモデルをなるべく多く並べて、数を出すのがコツです。

![](https://static.zenn.studio/user-upload/fc9f1dbf61fe-20261016.png)

OpenCode Go のときは Web 検索が使えないので、チェックは灰色になります。その代わり、数字には「推定」と筋道を書かせます。今回は OpenCode Go のモデルを10種類ほど回して20案出しました。

### 三 分類・選ぶ

案の左上の印で分析したい案を選び、画面のいちばん下の帯の「分析する」を押します。帯の「全部」「最新ラウンド」「外れ値」「バリエーション」で、一度に選ぶこともできます。

![](https://static.zenn.studio/user-upload/c936b9427d05-20261016.png)

骨格は3案ずつに分けて頼むので、20案でも途中で落ちにくくなりました。進み具合は「骨格 3/20」のように帯に出ます。途中で落ちた案があっても、取れた分は残ります。もう一度押せば、残りだけを頼み直します。

結果はこんな感じです。見事に収束しています。

![](https://static.zenn.studio/user-upload/f83464147ded-20261016.png)

いちばん大きな「収束」が8案、残りもほとんどが「SMB 向けの SFA/MA をどう軽くするか」の周りに、バリエーションとして2〜3案ずつ寄りました。外れ値は「SaaS を作らない：追客代行と貸しパイプ」の1案だけでした。これが事業企画の現実なんだと思います。

帯の「ファイル出力する」で、選んだ案を Markdown・CSV・JSON に書き出せます。会議の前に CSV を Excel で開いて、判断の一言と骨格を並べて眺めるのがおすすめです。

### 四 企画原案

案の「この案で原案へ」を押すと、原案の画面に移ります。今回は P01「SMB営業向け低摩擦SFA/MA：リスト育成とパイプライン回復」を選びました。

![](https://static.zenn.studio/user-upload/20778792aa50-20261016.png)

「ほかの案から取り込む」で、ほかの案の良いところだけを、選んだ案の芯を崩さずに取り込ませられます。今回は P03（入力しない前提の軽量SFA/CRM）・P15（入力しないSFA：ネクストアクション営業）・P19（営業とマーケを1本化するSMB向けMA）を取り込みました。外れ値を混ぜるのも面白いです。

原案ができると、節ごとの字数と機械検査の結果が出ます。指示を足して作り直すことも、節ごとに自分で直すこともできます。どちらも新しい版として残ります。

### 五 企画書たたき

聞き手・目的（社内承認／顧客提案／共有）・枚数・発表時間を決めて「たたきを作る」を押します。今回は社内の経営会議向けに、15枚・20分にしました。

v0.2.1 から、「社名」「発表日」「発表者」の欄もあります（どれも任意）。表紙とフッターに入れるのはこの3つだけで、空にした項目は「入れない」と渡す先に伝えます。理由は下の「やってみて困ったこと」に書きました。

「ツールに渡す」タブで、渡す先を選びます。

![](https://static.zenn.studio/user-upload/cba0d258bc72-20261016.png)

機械検査で、原案にない数字がスライドに出ていないかを確かめています。今回は「OK」でした。

Gemini を選んで「依頼文つき Markdown をダウンロード」し、Gemini に添付して「この内容に従ってプレゼン資料を作成してください」とだけ頼みました。

![](https://static.zenn.studio/user-upload/83eafa9e7851-20261016.png)

Google スライドに書き出すと、こうなります。

![](https://static.zenn.studio/user-upload/9347541a8f4e-20261016.png)

表紙に続いて、結論先出し・課題・解決・初版の範囲・市場・競合と勝ち筋・販売・儲け方・3年の売上計画・損益・体制・リスク・撤退と拡大の判断基準・お願い、の15枚が出てきました。3年の売上計画は、期中の社数×月額5万円×12か月が SaaS 売上と一致していて、スライドの中で検算しても筋が通っていました。撤退基準（「β後6か月で有料20社未満、または週次利用率30%未満なら撤退」）まで数字で切ってあるのは、経営層に一番効く一枚だと思います。

ここまで、テーマを入れてから約1時間でした。

### やってみて困ったこと：渡した先の AI が、社名と日付を勝手に埋める

できあがったスライドをよく見ると、フッターの日付がスライドごとにばらばらでした（2026.03.31、2026.04、2023.10…）。`[CURRENT_DATE]` という置き換え用の文字が残ったスライドもあり、社名は「COMPANY INC.」になっていました。構成案には日付も社名も書いていなかったので、Gemini が空いた欄を「それらしく」埋めたわけです。

数字の検査は構成案までしか届かないので、渡した先で足されたものは見えません。そこで v0.2.1 で次のようにしました。

- たたきに「社名」「発表日」「発表者」の欄を足し、依頼文・構成案・Word・Marp のすべてに書く。空の項目は「入れない」と書く。
- 依頼文に「構成案にない日付・社名・人名を足さない」「COMPANY INC.・[CURRENT_DATE]・xxxx のような仮の文字を入れない」「フッターの日付は全スライドで同じ発表日にする」を足す。
- 構成案の中に仮の文字があったり、表紙の日付が指定の発表日と違ったりしたら、機械で警告する。
- 「ツールに渡す」の画面に、仕上がったスライドで目で確かめること（表紙とフッターの日付・社名、原案にない数字）を一行出す。

AI に渡す依頼は、「何を書くか」だけでなく **「何を書かないか」と「空欄は空欄のまま」** まで言わないと、親切に埋められてしまいます。

## 4. まだ分かっていないこと・次にやること

- **渡した先で、本当に埋めなくなったか。** v0.2.1 の依頼文で Gemini・Copilot が仮の社名や日付を入れなくなるかは、まだ本物で試していません。
- **本物のプロバイダでの小分けの具合。** 3案ずつは偽のモデルで決めた値です。まだ落ちるなら `studio/settings.json` に `"skeleton_batch": 2` と書けば下げられます。
- **答え合わせ。** 原案の「要確認事項」と撤退基準は、本当は6〜12か月後に現実と照らすためのものです。企画を出して終わりではなく、台帳として持っておき、あとで答え合わせする仕組みにしたいと思っています。
- novel_studio の **執筆時のチェック** も、OpenRouter 以外では同じように時間切れになります。原因と対策は [Issue #13](https://github.com/InfraOjisan/novel_studio/issues/13) にまとめました。

## まとめ

- 小説の企画コンペは、そのまま事業企画に使えた。20案から経営会議資料まで約1時間。
- 事業企画はめちゃくちゃ収束する。ただし収束は「すぐ混む市場」の目安で、外れ値は差別化の候補。拾うのは人。
- 数字は出典か推定の筋道を残し、原案の要確認事項に残し、たたきで原案にない数字を機械で止める。
- スライドは作らない。「何枚目で何を言うか」と、渡す材料と依頼文までを作る。
- がんがん案を出させ、見込みのありそうなものを人間が選び、経営層にプレゼンする。そんな「企画の営み」は回せそうです。
