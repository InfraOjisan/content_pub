15年前のMacBook Airで、日本語のMarkdownが普通に書けるようになった。

Ubuntu Serverの上で、GUIを使わず、ターミナルに向かって文章を書く。カーソルで範囲を選び、コピーして、貼り付ける。書いた原稿はローカルに保存する。

ひととおり使ってみた感想は、「これ、十分使えるじゃないか」だった。

ただし、そこにたどり着くまでに、なぜかエディタをひとつ作ることになった。

## AI端末から文字入力専用機へ

このMacBook Airは、**11インチのLate 2010**。以前、バッテリーとSSDを交換し、Linuxを入れてAIコーディング端末として復活させた個体である。

[15年前のMacBook Airを、いま使えるポータブルAIコーディング端末にした](https://zenn.dev/infra_ojisan/articles/zenn-macbook-air-late2010-ai-terminal)

その後、もう少し新しい中古のLIFEBOOKで、普段使いしやすい環境を作る話に続いた。

[15年前のMacBook Airで学んだことを、2万円の中古LIFEBOOKで答え合わせした](https://zenn.dev/infra_ojisan/articles/zenn-lifebook-2019-allround-terminal)

では、MacBook Airはどうするのか。

この機械、キーボードがとても打ちやすい。11インチの画面も、文章を書くにはちょうどいい。本体もコンパクトで、持ち歩くのが苦にならない。バッテリーとSSDはもう交換してある。

だったら、持ち運び用のモノ書きツールにすればいい。

欲しいのは、だいたいこんなものだった。

- パカッと開けばすぐ書けて、閉じたらスリープする。
- 日本語のMarkdownを書いて保存できる。
- 書いたものを、あとでほかの端末に渡せる。

要件を書いていたら、一瞬「スマホでええやんけ」となった。

でも、このキーボードで書きたいのである。

それに、背面のリンゴマークが光る小さなMacで、ターミナルを開いて文章を書いているおじいさん。これ、ちょっとかっこよくないか。スタバに持ち込んだら、意識が高いのか時代に取り残されているのかわからない。Y2K感はある。いやでも15年前のPCを日常使いするのはSDGsだから令和なのか？

というわけで、MacBook Airの「ポメラ化」を進めることにした。

![MacBook Airのターミナルでこの記事の下書きを入力している様子](https://static.zenn.studio/user-upload/76bf954f452a-20261121.jpg)

## 既存のエディタを試してみた

基本の環境は、AI端末として使っていたときから変えていない。

```text
Ubuntu Server 24.04 LTS
  └─ kmscon
      └─ uim-fep + Mozc
          └─ tmux
              └─ エディタ
```

kmsconで日本語を表示し、uim-fepとMozcで日本語を入力する。tmuxは作業場所だ。

最初は、ここでVimやnanoを使えば済むと思っていた。

ところが、僕の環境では描画がどうにも怪しい。Vimを起動すると、前の画面の文字が残る。Escを押してCtrl+Lで再描画すればきれいになるが、毎回それをやるのも面倒だ。`vim --clean`でも変わらず、tmuxを挟むと改善することもあった。

nanoや、別に試したMarkdownエディタでも、この日本語入力・端末まわりの組み合わせでは画面が崩れる場面があった。

ここは、エディタ単体の問題と断定できていない。kmscon、uim-fep、tmux、それぞれの間で画面の扱いがうまく噛み合っていないのかもしれない。

スリープ復帰も、最初はバックライトだけ点いて文字が戻らないことがあった。ただ、試しているうちに普通に復帰するようになり、10分ほど閉じておいても書いていた画面へ戻れた。原因をきれいに解明できたわけではないが、いま手元では文章を書き続けられている。

もうひとつ、自分の操作の好みもあった。

僕がやりたいのは、カーソルで範囲を選んで、コピーや切り取りをして、好きな場所に貼ること。必要なら、コピーする内容ごとに名前を付けて、別々のバッファに入れておきたい。

VimやEmacsを使い込めばできることは多い。でも、今回はそれぞれの操作体系に合わせるより、欲しい操作だけがある道具にしたかった。

## MIFESやVZ Editorの操作感を思い出した

そこで思った。

欲しいのは、昔DOSで使っていたMIFESやVZ Editorのような編集機能ではないか。

カーソルを動かす。範囲を選ぶ。バッファに入れる。貼り付ける。ファイルに保存する。

あの頃、フロッピーで持ち歩いていたエディタの操作を思い出すと、いま欲しいものがずいぶんはっきりしてくる。大きな開発環境を作りたいわけではない。日本語の原稿を気持ちよく編集したい。

**なければ作ればいいんですよね。**

生成AIに仕様を伝えてソースを書いてもらい、ビルドして、実機で触って、気になるところを直す。必要なものを絞れば、いまなら手が届きそうだと思った。

そうして作ったのが、`mba-md`という小さなMarkdown専用エディタである。

実装はC++とncursesを中心にしている。日本語の文字処理やMarkdownの解析には既存のライブラリを使い、SFTP転送にはOpenSSHの`sftp`を呼ぶ。入力メソッドまで自作せず、すでに動いているuim-fepとMozcをそのまま使う。

ソースが手元にあるので、古い機械に合わせてコンパイルし直せるし、使いにくいところを自分の都合で変えられる。Linuxを入れた利点が、ここでも効いてきた。

ちなみにソースファイルは、たった30KBのtar.gz。FDD1枚分も必要ない。このファイルを持ち歩くだけで僕はどこでも文書を書けるのだ。とか言いながら大半はAIに書かせるのだが。

Markdownでサラッと書いとけば
~~~bash
pi -m claude-haiku-5-5 -p "@hoge.markdown に肉付けしてZennの記事として出力してgit pushして"
~~~
とかで終わる便利な世界。

## 選んでコピーして貼る

まず作ったのは、いちばん欲しかった編集操作だ。

文字を入力している最中に、別のモードへ切り替える必要はない。F2、またはCtrl+Tで選択を始め、カーソルを動かして範囲を決める。Ctrl+Cでコピー、Ctrl+Xで切り取り、Ctrl+Vで貼り付ける。

F2で範囲を選択
![F2で範囲を選択した画面](https://static.zenn.studio/user-upload/126144dd48e0-20261121.jpg)
*カーソルで必要な範囲を選ぶ。この操作感が欲しかった。*

コピーバッファには名前を付けられる。「引用」「メモ」など、用途別に分けておけば、別の文章をコピーしても前の内容を残しておける。エディタ内のバッファなので、OS全体のクリップボードとは別物だ。

Ctrl+Vで文章を繰り返し貼り付け
![Ctrl+Vで文章を繰り返し貼り付けた画面](https://static.zenn.studio/user-upload/b3068e757267-20261121.jpg)
*コピーした段落をCtrl+Vで貼り付ける。何度か試したので、同じ話が増殖している。*

もちろんUndoとRedoもある。

見た目は昔ながらでも、やりたい編集が迷わずできる。これだけで、文章を書く場所としてかなり落ち着いた。

## Markdownに絞って必要な機能を足す

ファイルはMarkdown専用にした。編集画面にはMarkdownの記法をそのまま表示する。整形済みのプレビューは、いまのところ付けていない。

その代わり、書いている途中で欲しくなる補助は入れた。

| 機能 | できること |
|---|---|
| 記法の補完 | 見出し、リスト、リンク、強調などのひな形を挿入 |
| 記法チェック | 見出し階層の飛びや空のリンク先などを警告 |
| リストの編集 | Enterで次の項目、Tabで段下げ、Shift+Tabで段上げ |
| 自動退避 | 保存前の編集を一定間隔で退避 |
| 原稿の選択 | 起動時に前回保存したフォルダのMarkdown一覧を表示 |

「文法チェック」はMarkdownの記法についてのものだ。日本語の誤字や文章の校正まではやらない。

F1でヘルプが出るのも、昔ながらのお約束である。

F1で操作一覧を表示
![F1で操作一覧を表示した画面](https://static.zenn.studio/user-upload/c15a124fbe6e-20261121.jpg)
*画面内に操作一覧を表示。コピーと貼り付けのほか、検索や置換も使える。*

原稿を別のホストに置くために、SFTPで送る機能も用意した。接続先は`config.yaml`に書き、ローカルに保存したあとで送信する構成にした。

SFTP保存（未設定の場合）
![SFTP保存しようとして未設定の表示](https://static.zenn.studio/user-upload/e491a28d289b-20261121.jpg)
*リモート保存を呼び出したところ。この時点では接続先が未設定なので、設定を促すメッセージが出ている。*

持ち出した先ではローカルに書き、通信できる場所へ戻ってから送ればいい。書くこと自体が、ネットワークの有無に左右されない形にしたかった。

## tmuxの作業場所もそのまま使える

エディタ専用の画面にしたからといって、ほかの作業ができなくなったわけではない。

tmuxの中で動かしているので、画面を分割したり、別のウィンドウへ移ったりできる。ネット接続がある場所なら、横でAIエージェントに調べものを頼むこともできるし、リモートホストにも接続できる。

tmuxでエディタと調べもの用画面（AIエージェント）に分割
![tmuxでエディタと調べもの用端末を開く](https://static.zenn.studio/user-upload/89acdd58c3a4-20261121.jpg)
*左で原稿を書き、右で別の処理を動かす。写真はネット接続がある環境での利用風景。*

普段は文章を書く画面を広く使い、必要なときだけ別の作業へ移る。このくらいの使い方が、11インチにはちょうどいい気がする。

## 実機で触ると細かい注文が出てくる

作ったものを使い始めると、欲しいものが具体的になってきた。

最初はF1のヘルプが異様にちらついた。コピーバッファの画面や、保存するファイル名の入力欄でも同じことが起きた。

そこで、メニューや入力欄の表示中に本文全体を繰り返し描き直さず、必要なところをまとめて更新するように変えた。

次に気になったのは、箇条書きの段下げだ。Tabで下げて、Shift+Tabで戻したい。これも付けた。

さらに、起動するたびに原稿のファイル名を入力するのが、地味に面倒だった。前回保存したローカルフォルダを覚えて、次回はその中のMarkdownを一覧から選べるようにした。前回の原稿を最初から選んでおけば、Enterだけで続きが書ける。

大きな新機能というほどのものではない。でも、毎回引っかかる小さな手間が減ると、ちゃんと自分の道具になってくる。

## ファンクションキーの割り当ては見直したい

そして、ひととおり使ってみて、もうひとつ気づいた。

**この頃のMacBook Airのファンクションキー、僕の使い方ではほぼ飾りだった。**

F1でヘルプ、F2で選択。昔のエディタを思い出しながら作っていると、ついそう割り当てたくなる。しかし、この実機で文章を書いていると、頻繁に使う操作をそこへ置くのは、どうにも使いづらい。

すでに、いくつかの操作はCtrlキーの組み合わせでも使える。

| 操作 | 現在使えるCtrlキーの組み合わせ |
|---|---|
| 選択開始と解除 | Ctrl+T |
| コピーバッファ名の指定 | Ctrl+B |
| Markdown補完 | Ctrl+K |
| 記法チェック | Ctrl+G |
| 保存 | Ctrl+S |
| 原稿を開く | Ctrl+O |

次はこの方向に寄せて、ヘルプや保存先の選択なども含めて割り当てを見直したい。日本語入力のCtrl+Spaceと、tmuxのプレフィックスに使っているCtrl+qは残す。

昔のエディタの操作感を思い出して作ったけれど、キー配置は目の前のキーボードに合わせないといけない。ここも、使ってみてわかったことだった。

## 次は茶店でバッテリーを試す

いまのところ、手元で文章を書く道具としては十分使えそうだ。

次は近所の茶店に持っていって、バッテリーがどれくらい持つか試したい。明日はネットワークにつながず、文字入力を中心に使うつもりなので、5〜6時間くらい持つのではないかと期待している。

これはまだ予想で、実測はこれからだ。バッテリーは交換しているが、古いIntel CPUの機械が、この使い方でどれだけ動くのかは確かめたい。

背面のリンゴが光る小さなMacで、コーヒーを飲みながら文章を書く。

そのためにエディタまで作ることになるとは思わなかった。でも、机の上で「十分使える」と思えたので、明日は持ち出してみる。
